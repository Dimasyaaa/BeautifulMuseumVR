## Описание проекта

**BeautifulMuseumVR** — приложение виртуальной реальности, представляющее собой интерактивный музей, в котором пользователь может знакомиться с экспонатами в трёхмерном пространстве.

Проект разработан на Godot Engine с использованием GDScript и технологий OpenXR. Архитектура приложения предусматривает взаимодействие VR-клиента с отдельной серверной частью на FastAPI и базой данных PostgreSQL.

В отличие от традиционного музейного каталога, виртуальная среда позволяет организовать знакомство с экспозицией непосредственно внутри трёхмерного пространства. Серверная архитектура, в свою очередь, отделяет логику приложения от обработки запросов и хранения данных.

Проект объединяет технологии виртуальной реальности, клиент-серверного взаимодействия и реляционных баз данных в рамках единого программного решения.

## Цель и задачи

**Цель проекта** — разработать VR-приложение виртуального музея с возможностью взаимодействия с серверными сервисами и базой данных.

Основные задачи:

- Создание трёхмерного музейного пространства.
- Подготовка сцен, моделей и материалов для виртуального окружения.
- Интеграция OpenXR и инструментов Godot XR Tools.
- Организация сетевого взаимодействия между VR-клиентом и сервером.
- Выделение клиентского компонента для работы с API.
- Организация пользовательской сессии.
- Использование FastAPI для построения серверной части.
- Подключение PostgreSQL для хранения структурированных данных.
- Разделение визуальной логики, сетевого взаимодействия и серверной обработки.

## Функциональные возможности

### 1. Виртуальное музейное пространство

- Создание трёхмерного окружения для размещения музейной экспозиции.
- Использование моделей и материалов для оформления виртуальной среды.
- Организация сцен и ресурсов средствами Godot Engine.
- Возможность дальнейшего расширения музейного пространства новыми объектами и экспозициями.

- Интеграция OpenXR.
- Использование Godot XR Tools для разработки VR-взаимодействий.

- Использование карты действий OpenXR для организации ввода.
- Подготовка приложения к работе с совместимым VR-оборудованием.

- Выделение отдельного компонента `ApiClient` для сетевого взаимодействия.
- Организация обмена данными между клиентским приложением и серверной частью.
- Использование HTTP и структурированных данных для взаимодействия с API.
- Разделение сетевой логики и логики отображения музейной сцены.

- Выделение компонента `UserSession` для работы с состоянием пользовательской сессии.
- Централизация соответствующей логики на стороне клиента.
- Возможность развития механизма взаимодействия с пользовательскими данными.

### 5. Серверная часть и база данных

- Применение PostgreSQL для хранения данных.
- Размещение серверной части в отдельном каталоге `_backend`.
- Разделение клиентской и серверной частей приложения.

### 6. Расширяемость архитектуры

- Раздельное хранение сцен, скриптов, моделей и материалов.
- Использование отдельных компонентов для выполнения специализированных задач.
- Возможность расширения проекта дополнительными сценами и серверными функциями.
- Поддержка дальнейшего развития музейной экспозиции и взаимодействия с данными.

## Архитектура проекта

Приложение построено на основе разделения клиентской и серверной частей. VR-клиент отвечает за виртуальное пространство и взаимодействие с пользователем, а серверный компонент предоставляет API и работает с базой данных.

### Основные компоненты

**VR-клиент — Godot Engine**

Отвечает за загрузку сцен, отображение трёхмерного окружения и выполнение клиентской логики. Конфигурация проекта хранится в файле `project.godot`.

**ApiClient**

Компонент клиентского приложения, предназначенный для организации взаимодействия с серверным API.

**UserSession**

Компонент, выделяющий логику управления пользовательской сессией.

**FastAPI**

Серверный компонент, обеспечивающий обработку запросов и взаимодействие между клиентом и серверными ресурсами.

**PostgreSQL**

Система управления реляционными базами данных, предназначенная для серверного хранения структурированной информации.

## Структура проекта

```text
BeautifulMuseumVR/
│
├── Audio/                  # Аудиоресурсы
├── Materials/              # Материалы и визуальные ресурсы
├── Models/                 # Трёхмерные модели
├── Scenes/                 # Сцены Godot
├── Scripts/                # Скрипты клиентского приложения
│
├── _backend/               # Серверная часть
│
├── addons/                 # Дополнительные расширения Godot
│   ├── godot-xr-tools/     # Инструменты VR-разработки
│   └── godot_xr-simulator/           # Дополнительные инструменты редактора
│
├── Demonstration/          # Скриншоты проекта
│
├── icon.svg                # Иконка приложения
├── openxr_action_map.tres  # Карта действий OpenXR
├── export_presets.cfg      # Настройки экспорта
├── project.godot           # Конфигурация проекта
└── README.md               # Документация проекта
```

Назначение основных каталогов:

- **`Audio/`** — аудиоресурсы проекта.
- **`Materials/`** — материалы, используемые для оформления объектов.
- **`Models/`** — трёхмерные модели музейного окружения.
- **`Scenes/`** — сцены виртуального пространства и связанные игровые объекты.
- **`Scripts/`** — скрипты клиентской логики.
- **`_backend/`** — серверная часть приложения.
- **`addons/`** — подключённые расширения Godot и инструменты разработки.
- **`Demonstration/`** — изображения для визуальной демонстрации проекта.

Файлы `project.godot`, `openxr_action_map.tres` и `export_presets.cfg` используются для конфигурации проекта, настройки VR-ввода и параметров экспорта.

## Сценарий взаимодействия

Общая логика работы приложения предполагает взаимодействие пользователя с виртуальным музейным пространством и обращение клиентской части к серверным ресурсам.

1. **Запуск приложения.** Загружается проект Godot и подготавливается виртуальное окружение.
2. **Взаимодействие с музеем.** Пользователь работает с трёхмерной сценой посредством VR-интерфейса.
3. **Обращение к серверу.** Клиентская логика использует компонент `ApiClient` для организации запросов к API.
4. **Обработка запроса.** Серверная часть на FastAPI выполняет предусмотренную обработку данных.
5. **Работа с хранилищем.** PostgreSQL используется сервером для взаимодействия с базой данных.
6. **Возврат данных.** Сервер передаёт результат клиенту, после чего приложение может использовать его в своей логике.

Конкретные операции с экспонатами и пользовательскими данными определяются реализованными маршрутами API и соответствующей логикой серверной части.

## Установка и запуск

### Необходимые инструменты

- [Godot Engine](https://godotengine.org/download/).
- Совместимое окружение OpenXR для запуска VR-приложения.
- Совместимая VR-гарнитура для тестирования виртуальной реальности.
- Python и зависимости серверной части.
- PostgreSQL для работы с базой данных.

### Запуск клиентской части

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/Dimasyaaa/BeautifulMuseumVR.git
   ```

2. Перейдите в каталог проекта:

   ```bash
   cd BeautifulMuseumVR
   ```

3. Откройте Godot Engine.
4. Импортируйте проект, выбрав файл `project.godot`.
5. Дождитесь завершения импорта ресурсов.
6. Проверьте настройки OpenXR и подключения VR-устройства.
7. Запустите проект из редактора.

### Запуск серверной части

Серверная часть расположена в каталоге `_backend`.

Перед запуском необходимо:

1. Проверить инструкции и файлы конфигурации backend.
2. Установить зависимости Python, предусмотренные проектом.
3. Настроить подключение к PostgreSQL.
4. Запустить сервер согласно предусмотренной точке входа.
5. Проверить доступность API и корректность адреса сервера в клиентском приложении.

Точные команды запуска зависят от конфигурации серверной части и её файлов зависимостей.
